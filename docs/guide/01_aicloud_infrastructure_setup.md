# 第 1 章：晶創雲雲平台基礎設施與 VM 建立

本章只聚焦一個可驗收成果：**建立一台 VM，狀態為 `active`，並能透過 Console 登入。** 負載平衡、自動擴展與檔案共享等功能留到有實際需求時再學習。

晶創雲雲平台的畫面、規格與配額可能隨專案及版本不同。本章操作前請同時開啟[晶創雲雲平台官方使用手冊](https://docs.central.iic.nchc.org.tw/user-panel/)比對當下畫面。

## 1. 課前檢查

開始建立資源前，先確認：

- 已登入正確的專案與區域。
- 知道自己是專案管理者或一般使用者。
- 專案尚有 VM、vCPU、記憶體及儲存配額。
- 專案已有可用的虛擬網路；若後續要下載套件，該網路需要可連接外部網路。
- 已確認課程指定的映像檔、硬體規格、安全群組與命名規則。
- 知道資源從建立到刪除之間可能持續計費；停止 VM 不一定等於停止所有費用。

> 硬體選項會依伺服器與專案配置而不同。教材中的規格只能當作示例，請以專案畫面及[官方 AI-Cloud 價目表](https://docs.central.iic.nchc.org.tw/user-panel/price/ai-cloud)為準。

## 2. 平台功能地圖與課程範圍

晶創雲雲平台提供多種 IaaS 功能，但本課程不需要一次操作全部服務：

```text
晶創雲雲平台（AI-Cloud）
├── 本課程會操作
│   ├── 虛擬機器、映像檔與鑰匙對
│   └── 虛擬網路與安全群組
├── 視專案需要
│   ├── 額外虛擬磁碟
│   └── 浮動 IP／跳板機
└── 延伸認識
    ├── 負載平衡與自動擴展
    └── 檔案共享
```

負載平衡、自動擴展與檔案共享適合多節點或高可用情境，不是本課程建立單一 Chatbot 的必要條件。浮動 IP 也不應配置給每一台 VM；是否使用及如何經由跳板機連線，由講師依專案網路統一規劃。

## 3. 先建立鑰匙對

在建立 VM 前，先從「虛擬機器 → 鑰匙對」建立或匯入鑰匙對。

1. 輸入容易辨識的名稱，例如 `course-你的學號`。
2. 若平台產生私鑰，立即下載 `.pem` 檔案。
3. 將私鑰存放在個人電腦的安全位置，不要上傳雲端硬碟、群組聊天或 Git。
4. macOS／Linux 可在本機執行：

```bash
chmod 600 ~/.ssh/course-your-id.pem
```

平台不會替使用者保留可再次下載的私鑰；遺失時應建立新的鑰匙對，不要向同學借用。詳細流程請參考[官方鑰匙對文件](https://docs.central.iic.nchc.org.tw/user-panel/virtual-platform/key-pair)。

### 驗收點 A

- 看得到鑰匙對名稱。
- 私鑰已下載並妥善保存。
- 私鑰沒有被加入課程專案或 Git。

## 4. 認識最小必要架構

```text
[個人電腦／Antigravity]
          │ SSH
          ▼
[晶創雲 VM]
├── Ubuntu
├── 私有 IP
├── 虛擬網路
└── 安全群組
          │ Egress
          ▼
[套件網站與模型 API]
```

本課程的開發服務會透過 Antigravity Ports 預覽，正式服務則透過 Cloudflare Tunnel 發布，因此**不需要在安全群組開放 3000、4000、8000、80 或 443 給全世界**。

## 5. 建立 VM 的七個步驟

從「虛擬機器 → 虛擬機器管理」點擊「＋建立」。官方精靈目前依序包含以下步驟，實際欄位以平台畫面為準。

### 步驟 1：基本設定

- 名稱：使用課程約定格式，例如 `aicloud-你的學號`。
- 描述：寫明課程、擁有者及用途。
- 映像檔：選擇課程指定的 Ubuntu LTS 公用映像檔。

不要在教材中假設某個版本永遠是「最新」；開課前由講師公布已驗證版本。

### 步驟 2：硬體設定

模型推論會由外部 API 完成，VM 主要執行 LiteLLM、Next.js 與開發工具。課堂通常從可用的最小 Basic 規格開始即可，資源不足再調整。

選型時確認：

- 規格可選且沒有超過專案配額。
- 系統碟足以安裝容器映像與 Node.js 套件。
- 已了解每小時費率及整堂課的預估成本。

課堂選型可使用下列判斷，不把當期規格名稱寫成永久保證：

| 情境 | 建議起點 | 調整時機 |
| :--- | :--- | :--- |
| 個人練習、依序啟動服務 | 專案可用的最小 Basic 規格 | 記憶體不足、Build 過慢或容器被終止 |
| 同時執行 LiteLLM、PostgreSQL、Chatbot | Basic 類型中具較多記憶體的規格 | 先觀察實際用量，再依配額升級 |
| CPU／Memory 特殊工作負載 | 不作為本課程預設 | 有量測結果與明確需求才選用 |

開課前由講師依[官方 AI-Cloud 價目表](https://docs.central.iic.nchc.org.tw/user-panel/price/ai-cloud)、專案配額及實測結果公布課堂規格。

### 步驟 3：虛擬網路

- 至少新增一張虛擬網卡。
- 選擇講師指定的虛擬網路。
- 套用講師指定的安全群組。

安全群組預設規則與課程新增規則必須分開說明。不要把某個場域的 SSH 網段寫成所有專案都適用的固定值。詳細欄位請參考[官方安全群組文件](https://docs.central.iic.nchc.org.tw/user-panel/virtual-platform/security-group)。

| 規則類型 | 本課程處理方式 |
| :--- | :--- |
| 平台預設 Egress：`169.254.169.254/32`、TCP 80 | 保留，不任意刪除或修改 |
| 平台預設 Egress：`0.0.0.0/0`、UDP 67–68 | 保留，不任意刪除或修改 |
| SSH Ingress | 只允許講師公告的來源網段或跳板機 |
| 3000、4000、8000、80、443 Ingress | 不因開發預覽而對公網開放 |
| DNS、HTTPS 與其他 Egress | 依專案網路政策及實際上游需求設定 |

不要把範例 CIDR、公網 IP 或其他班級的安全群組直接複製到自己的專案。

### 步驟 4：虛擬磁碟（選擇性）

本課程通常不需要額外資料磁碟。若建立額外磁碟，要記錄掛載位置、費用與課後清理方式。

### 步驟 5：認證

- 啟用鑰匙對認證。
- 選擇本章前面建立的鑰匙對。
- 是否設定密碼依專案安全政策決定。

### 步驟 6：初始化指令（選擇性）

第一次授課建議先留空，讓學員在第 2 章透過 Antigravity 看見並理解每項安裝操作。已有經驗的班級才使用經審核的 cloud-init 腳本。

### 步驟 7：檢閱＋建立

送出前再次核對：名稱、映像檔、硬體規格、網路、安全群組與鑰匙對。建立後可能出現：

- `active`：可以開始使用。
- `under review`：等待專案管理者審核。
- `error`：先查看錯誤與配額，不要連續重複建立。

完整畫面與狀態說明請參考[官方虛擬機器文件](https://docs.central.iic.nchc.org.tw/user-panel/virtual-platform/virtual-machine)。

## 6. 使用 Console 做第一次登入

先使用平台提供的 Console 驗證 VM 本身能正常啟動與登入。成功後執行：

```bash
hostname
whoami
ip address
cat /etc/os-release
```

記錄 VM 名稱、使用者名稱、私有 IP 與 Ubuntu 版本，但不要記錄或分享密碼及私鑰內容。

### 驗收點 B

- VM 狀態為 `active`。
- Console 可登入。
- `whoami` 與預期帳號相符。
- VM 取得預期的私有 IP。

### 交接到第 2 章

建立一份不含 Secret 的 VM 交接紀錄：

| 欄位 | 記錄內容 |
| :--- | :--- |
| 專案／區域 | 目前操作的專案與區域 |
| VM | 名稱、狀態、映像版本與硬體規格 |
| 登入 | 預期帳號與直接連線／跳板機情境 |
| 網路 | 私有 IP、虛擬網路與安全群組名稱 |
| 鑰匙對 | 平台上的鑰匙對名稱與本機私鑰路徑，不記錄私鑰內容 |
| 責任 | 建立時間、費率確認與課後清理人員 |

這份紀錄會在第 2 章轉換成 SSH 設定。不要把密碼、私鑰、Token 或真實憑證寫進共用文件。

## 7. 常見問題

### 規格無法選擇

檢查專案配額與可用資源。官方文件指出，規格選項可能因硬體配置與專案設定不同。

### VM 一直顯示 under review

這不是建立失敗，而是需要專案管理者審核。

### Console 可登入，但不能連外

確認虛擬網路是否已連結外部網路，以及安全群組必要的 Egress 規則是否仍存在。不要為了解決連線問題而直接開放所有 Ingress。

### 私鑰遺失

不要請別人傳送私鑰。建立新的鑰匙對，並依專案流程更新登入方式或重建課程 VM。
